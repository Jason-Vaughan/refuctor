# Refuctor Cursor Rules
# "No Bloat. No Debt. No Bullshit."

## 📋 CURSOR RULES CLONE WORKFLOW
**This file (`refuctorrulesclone.txt`) is a staging/backup file for cursor rules management.**

**Why this exists:**
- Cursor rules are now managed through Cursor's interface (not as a file)
- Interface-managed rules can't be edited programmatically
- This clone file serves as the editable source of truth

**Workflow:**
1. AI makes changes to this clone file when cursor rules need updates
2. AI will ALWAYS prompt you to copy the entire contents to Cursor's interface
3. You manually copy/paste the full content to update the live rules
4. This ensures cursor rules stay synchronized with our development needs

**When to update the live rules:**
- Any time this file is modified during a session
- When you see a prompt: "🚨 CURSOR RULES UPDATED - Please copy refuctorrulesclone.txt to Cursor interface"

## 🎯 Core Philosophy
- **MINIMUM BLOAT**: Every line of code must justify its existence
- **IMMEDIATE TECH DEBT**: Address technical debt the moment it's identified
- **SINGLE SOURCE OF TRUTH**: All documentation lives in README.md and REFUCTOR_ROADMAP.md
- **SNARKY BUT FUNCTIONAL**: Maintain Refuctor's debt-cleansing personality without sacrificing performance

## 🚫 Anti-Bloat Enforcement
- NO unused imports, variables, or functions
- NO commented-out code blocks (delete it)
- NO duplicate logic (DRY principle, but don't over-abstract)
- NO "TODO" comments (fix it now or create an issue)
- NO dependencies without clear justification
- NO config files for config files
- NO premature optimization, but NO obvious performance sins

## 📁 File Management
- Keep file count minimal - prefer larger cohesive files over micro-files
- Delete temp files, test artifacts, and debug outputs immediately
- Use .gitignore aggressively for build artifacts
- One source of truth: if it's in README.md or ROADMAP.md, don't duplicate it elsewhere

## 🎨 Refuctor Brand Guidelines
- Maintain snarky debt-cleansing personality in CLI output, error messages, and logs
- Use Refuctor terminology: "Debt Collector", "Goons", "Foreclosure", "Repossession"
- Color scheme: debt-red warnings, clean-green success, dark theme
- Financial metaphors: "refinance", "bankruptcy", "collection agency", "interest accruing"

## 🧹 Session Wrap Protocol (Enhanced)
When user says "session wrap" or "let's wrap", execute this comprehensive 9-step procedure:

### 1. Session Summary 📋
- **Accomplishments**: What we built, fixed, or improved
- **Technical breakthroughs**: Solutions to blockers or architecture decisions
- **Testing results**: What works, what broke, validation outcomes
- **Code quality improvements**: Refactoring, optimization, cleanup performed
- **Performance metrics**: Build times, bundle sizes, runtime improvements

### 2. Next Session Priorities 🎯
- **Critical path items**: Must-do tasks for next session
- **Specific success criteria**: Measurable goals to achieve
- **Roadmap milestone progress**: Which milestones advanced/completed
- **Technical blockers**: Known issues requiring resolution
- **Risk assessments**: Potential obstacles and mitigation strategies

### 3. Documentation Maintenance 📚
- **Update README.md**: Add new features, modify installation instructions, update status
- **Update REFUCTOR_ROADMAP.md**: Mark milestones complete, adjust timeline, add discoveries
- **Update cursor rules**: Reflect any new patterns, rules, or architecture changes through Cursor interface
- **Brand guidelines compliance**: Ensure snarky debt-cleansing personality maintained
- **Documentation drift detection**: Find outdated guides, stale instructions
- **Cross-reference validation**: Check internal links and file references

### 4. Technical Debt Cleanup 🧹
- **AUTOMATED DEBT SCANNING**: Run comprehensive tech debt detection
- **Update TECHDEBT.md**: Log new issues found, mark resolved items complete
- **Cursor Error Analysis**: Count and categorize all IDE warning indicators
- **Linting Issues**: `npx markdownlint-cli *.md` and other applicable linters
- **Spell Check Issues**: `npx cspell "**/*.{md,js,json,ts}" "*.mdc"` across all relevant files  
- **Unused Dependencies**: Analyze package.json vs actual imports
- **Dead Code Detection**: Functions, variables, imports no longer referenced
- **TODO Comment Audit**: Find orphaned TODOs without corresponding issues
- **Security Vulnerabilities**: `npm audit` and dependency analysis
- **Performance Bottlenecks**: Bundle size, load time, memory usage analysis
- **Configuration Drift**: Validate all config files align with project standards
- **Broken Reference Cleanup**: Fix invalid file paths, missing dependencies
- **Recommend specific files for removal** with justification
- **DEBT ACCOUNTABILITY**: Every new debt item gets session timestamp and priority

### 5. Configuration Validation ⚙️
- **Verify .gitignore**: Add new patterns for build artifacts, temp files
- **Check package.json**: Version consistency, dependency alignment, script validity
- **Validate cursor configurations**: Interface-managed rules, workspace settings
- **Environment setup verification**: Development tools, paths, permissions
- **Cross-platform compatibility**: Ensure setup works on different systems

### 6. Git Management Strategy 🔀
**Local Development Commits (Full Project):**

## 🛠️ Code Quality Standards
- Functions should do one thing well
- Variable names should be descriptive (no single letters except loop counters)
- Error messages should be helpful AND snarky (debt-cleansing personality)
- Comments explain WHY, not WHAT
- No magic numbers - use named constants
- Async/await over Promises over callbacks

## 🎯 Refuctor-Specific Rules
- CLI commands should have debt-cleansing personality: "refuctor scan", "refuctor shame", "refuctor fix"
- Error messages should use financial metaphors: "Your code is in foreclosure", "Debt levels critical"
- Success messages should be celebratory: "Debt eliminated! You magnificent debt-slayer!"
- All debt priorities use P1-P4 system with snarky descriptions
- Follow established Puberty Labs humor patterns

## 🚨 Automatic Actions
- Run linter after every code change
- Clean up imports on save
- Validate JSON configs on modification
- Check for dead code after refactoring
- Verify all external links in documentation

## 💡 Decision Framework
Before adding anything, ask:
1. Does this solve a real problem?
2. Is there a simpler way?
3. Will this create maintenance burden?
4. Does it align with Refuctor's debt-cleansing mission?
5. Can we delete something else instead?
